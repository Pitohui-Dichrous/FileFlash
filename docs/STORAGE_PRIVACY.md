# FileFlash 2.0.0 存储与隐私

FileFlash 的图片、视频缩略图只在内存中缓存，不写入磁盘。APP 的压缩缩略图缓存上限为 8 MiB，另有可见行的解码图片；网页最多保留 16 张可见小图、4 MiB 压缩数据，移出视区后释放。其它文件或不支持的媒体显示分类图标。配对二维码也只保存在内存中。

## 文件如何保留

| 内容 | 保存及清理规则 |
| --- | --- |
| 用户选择发送的原文件 | 通过系统授予的 URI 读取，不另存整份，不因清理缓存而删除。 |
| 未传完的临时数据 | 位于应用私有目录，用于续传；原生接收与主机上传共用 256 MiB 的闲置数据清理目标。 |
| 新版服务端已收全、尚未点保存的文件 | 默认临时中转，位于私有目录；可供其他已连接设备下载，与断点共用过期和容量清理规则，不自动发布到下载目录。 |
| 用户点过保存但失败的文件、原生客户端下载后待保存文件 | 自动清理保留完整数据供重试，升级前的完整待保存数据也受保护；确认手动“清理”或单独“丢弃”后会删除。 |
| 已保存的接收文件 | 保存在“下载 / FileFlash”。保存状态和位置可靠落盘、文件能重新读取后，自动删除私有重复副本，主机从下载目录继续共享。 |
| 任务和保存记录 | 仅含文件名、状态、位置、校验和等元数据。网页完成/取消历史最多 100 条、7 天；原生完成记录最多 150 条，保存位置索引单独保留，防止重启重复保存。手动“清理”会清空两类历史，不删除公开下载文件。 |

只有用户点“保存”时，服务端才发布到系统下载目录。保存期间会短暂存在两份数据，应预留约文件大小两倍的空间。保存失败、文件正被下载或删除暂时失败时，私有副本可能继续保留，后续重试或维护时释放。仅作 B→A→C 中转时不创建公共下载目录副本，但完整临时文件仍占用 A 的私有存储。

自动清理时，闲置断点和未保存的临时中转文件一般在 **24 小时无活动**后过期。超过共同 **256 MiB** 目标时，优先回收旧数据，并保护最近 **30 分钟**内使用的文件；活动上传、完整校验、下载及保存不受预算裁剪。实际下载开始和结束更新闲置时间，列表刷新、HEAD 和生成下载链接不续期。保存意图在复制前持久化，失败或重启后保留供重试。256 MiB 是闲置数据清理目标，**不是全部存储占用的硬上限**。

维护复用应用内现有状态循环，并在下次启动时补做，不新增定时后台任务。应用进程已终止时不会为了清理另行唤醒，所以 24 小时不是到点必定删除的计时承诺。原生断点清理后需要从头传输。

0.1.5-test.1 网页上传不再保存断点。失败、取消或服务重启后，未完成的连续上传会清理临时文件；网页重试从零开始。已经接收完整的文件仍按临时中转规则处理，点击“保存”后才导出到下载目录。

## 暂停、划走和手动清理

原生“暂停”停止当前网络请求并保留断点；从最近任务中划走应用不会主动删除断点，也不会主动终止已启动的传输前台服务。应用和通知中的“停止”会关闭共享及传输、撤销连接。系统限制或终止进程后，下次打开需重新连接并重试，仍受上述断点保留规则约束。

“记录”页显示临时占用和闲置数据。“清理”经确认后停止并丢弃所有未完成任务，清空任务历史、已保存历史、断点与临时中转文件，包括保存失败或旧版遗留的待保存数据。清理会先取消活动读写并等待结束，不在写入过程中直接删除文件。“丢弃”则只处理选定的临时文件或未完成任务。

两者都保留发送原文件和已完整保存到 **Download/FileFlash** 的文件。临时文件清理后，对应的共享入口失效，需要重新上传；原始共享文件、文字及配对保留。已保存历史清空后，可在“使用与权限”点击 **下载目录** 打开公开文件；无法直达时回退系统下载页。目录定位使用系统标识，不依赖“下载”等本地化显示名称。

## 卸载后留下什么

Android 卸载应用会删除应用私有文件、缓存和设置；FileFlash 已禁用应用数据备份与设备迁移。已接收并保存到公共下载目录的文件属于用户文件，卸载后保留，需要时由用户在系统文件应用中删除。不能依赖卸载时回调去清除这些文件：被卸载应用收不到自身的移除广播。[Android 专属存储](https://developer.android.com/training/data-storage/app-specific)、[共享存储](https://developer.android.com/training/data-storage/shared)、[卸载广播说明](https://developer.android.com/reference/android/content/Intent#ACTION_PACKAGE_REMOVED)

另有一个系统边界：如果保存到下载目录期间进程被突然终止，随后未经再次打开便立即卸载，未完成的隐藏 MediaStore 项目可能暂时保留。应用正常失败时会删除它，下次启动也会恢复清理；卸载后则由系统按过期规则处理，通常为 7 天后、设备空闲时清除，不能保证卸载瞬间外部目录零残留。Android 14 的包移除处理会解除其余媒体记录的所属关系，没有承诺立即删除这类下载项。[Android 过期规则](https://developer.android.com/reference/android/provider/MediaStore.MediaColumns#DATE_EXPIRES)、[Android 14 MediaProvider 实现](https://android.googlesource.com/platform/packages/providers/MediaProvider/+/refs/heads/android14-release/src/com/android/providers/media/MediaProvider.java#1877)

iPhone 使用网页和 Apple 系统快捷指令，不安装第三方 FileFlash iOS 应用。网页仅存连接及任务元数据，不持久化上传文件字节，不注册离线缓存服务。快捷指令没有另存媒体、写日志或持久保存地址和凭据的动作；系统分享准备的暂存由 iOS 管理。Safari 下载的安装文件、已添加的快捷指令、网站数据和浏览器缓存不受 Android 卸载影响，需要时可在 iPhone 删除。该路径不要求先在「文件」生成媒体副本。

## 隐私审查范围

应用、网页和快捷指令的运行代码未发现广告、统计、追踪 SDK、云服务调用或开机自启入口。网页资源随 APK 打包，仅向当前主机发起同源请求；HTTP 响应禁止缓存，Android 客户端也禁用 HTTP 缓存。相机用于扫码，文件通过系统选择器或分享表单授权读取。构建时对公开模板的外部签名与独立核验见 [IOS_SHARE.md](IOS_SHARE.md)，不发送设备凭据或用户内容。

这些结论来自源码与配置审查，不是抓包结果，也不代表对所有系统行为的绝对保证。本版本在可信局域网使用未加密 HTTP，令牌提供访问控制，不提供内容加密。各版本的本机与实体设备验证分别记录于 [验证结果](TEST_RESULTS.md) 和 [酸性设计记录](acid-design/README.md)。
