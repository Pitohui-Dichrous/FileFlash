# FileFlash 架构

本文对应 0.1.10，HTTP 协议版本仍为 v1；本次补齐系统分享上传缺少的文件后缀，并让下载响应的兼容文件名保留后缀。安卓界面及连接清理沿用 0.1.9，快捷指令沿用 0.1.8。

## 模块

- `app`：Kotlin / Jetpack Compose Android 应用。最低 Android 10（API 29），目标 Android 17；同一 APK 包含主机和客户端。最低版本受当前 MediaStore Downloads 保存流程约束。
- `core`：不依赖 Android 的 Java 传输内核；Android 和本机集成测试使用相同实现。
- `app/src/main/assets/web`：原生 HTML、CSS、JavaScript。由 Android 本地服务提供，资源全部随 APK 打包。
- `FileFlash.shortcut`：签名的 Apple 系统分享工作流；公开源在 `scripts/shortcut`。没有转码、持久化媒体或运行期外网服务动作。

## 数据路径

Android 主机通过系统文件选择器取得 URI 读取权限，只公开用户选中的文件。iPhone 在 Safari 打开二维码地址；另一台 Android 通过原生扫码或输入地址连接。配对后双方使用同一个会话发送文件和文字，不需要交换主机角色。

iPhone 照片与视频从系统照片分享「当前」格式给 FileFlash 快捷指令，扫码配对后按文件发送原始 File 请求体，避开 Safari 照片选择器。接口兼容固定长度及受限 chunked；上传仍先临时中转。用户已确认 0.1.8 的大小文件均可发送。

系统分享上传完成后，服务端最多读取临时文件头 64 KiB，用可靠签名补齐缺失后缀与 MIME；无法识别的无后缀文件使用 `.bin`。已有格式后缀保留，名称中的数字或版本尾段只有在识别出媒体时才追加真实后缀。修正后先持久化再公开，下载头、共享列表及显式保存使用一致的名称；正文、摘要与网页/原生上传协议不变，不生成检测缓存，也不迁移旧文件。

原生客户端上传串行发送有独立 SHA-256 的小块。服务器校验每块后持久化偏移；恢复时使用文件完整摘要和随机恢复凭据识别任务。完成接口再次校验完整文件，校验通过才公开文件。

网页使用一次连续文件请求，以固定缓冲直接写入临时文件，不保存分块断点，也不逐块计算或核对客户端摘要。服务器只在末尾同步数据并确认总长度，接收过程中顺带生成接收副本的 SHA-256。该摘要用于标识接收内容，没有与发送端原文件进行独立比对。失败或取消删除本次临时数据，进程异常结束时在重建内核时清理未完成请求。下载继续使用流式响应、64 位长度和 HTTP Range。

Android 服务端接收文件完成校验后先在私有目录临时共享，可作为 B→A→C 中转。仅在主机用户点“保存”后，通过持久化保存意图和活动锁保护源文件，再发布到系统下载目录。发布使用 MediaStore 待完成状态及可恢复日志；可靠保存后释放私有副本，并将同一共享 ID 绑定到该系统文件。保存期间可能短暂占两份空间，失败或中断后保留完整数据供手动重试。原生客户端主动“接收”仍是下载并保存。

下载目录中的文件由系统文件应用管理。网页下载交给 Safari 下载管理器，不将文件持久化到 localStorage、IndexedDB 或网页缓存。网页不会虚构浏览器没有提供的保存进度或自动恢复能力。

文字以 UTF-8 JSON 传送，直接显示为可选文本。网页复制支持能力检测，并保留手动选择复制。

## 生命周期

服务端沿用既有 900 ms 状态轮询，接收提示仅保存在有界内存中。监听前建立旧任务基线，新的上传或偏移增长才激活提示；首次被观察时已完成的小文件也能提示。多个上传合并显示，未知长度使用不定进度。长期无新数据只提示“等待数据”，不推断失败；快照读取失败不视为任务消失。停止或重启使用服务实例及代际检查，防止旧结果恢复过时提示。顶部卡片在各标签页可见，不增加传输确认、落盘或后台任务。

用户主动启动的传输在 `dataSync` 前台服务中运行，通知提供停止入口。应用页面切换或从最近任务中划走不会主动停止该服务，也不会立即删除暂停断点。服务采用 `START_NOT_STICKY`，没有开机自启入口；停止时关闭连接、撤销会话，遵守系统超时。锁屏、省电和系统终止仍可能中断任务；Safari 上传应保持网页在前台。

存储维护在应用启动以及现有状态循环中执行，不新增定时后台任务；没有临时数据及活动传输时挂起等待，有临时数据时在进程内按分钟维护。进程已终止时不会另行唤醒，过期内容在下次启动处理。闲置断点与未保存的完整中转文件共用 256 MiB 目标，24 小时无活动时过期；预算回收保护最近 30 分钟内使用的任务。下载从打开源文件前到流关闭后持活动锁，避免清理竞争；实际下载更新闲置时间，状态轮询不续期。保存中、保存失败待重试及旧版完整待保存文件继续保护。已保存文件不计入闲置目标，目标也不是全部占用的硬上限。

文件列表使用通用图标，没有图片/视频磁盘缩略图缓存。配对二维码只在 Compose 组件范围内持有内存位图，组件离开组合后不再持有该引用，由系统回收内存。

网页完成/确认取消历史最多 100 条、保留 7 天，完成后释放文件引用及临时凭据；失败重试从零开始，刷新后需重新选文件。原生任务列表保留最多 150 条完成记录，保存索引独立保留，以免重启后重复导出用户文件。更多清理和卸载边界见 [STORAGE_PRIVACY.md](STORAGE_PRIVACY.md)。

## 安全边界

二维码片段包含随机配对凭据；配对后使用会话凭据访问接口。未配对请求无法列出文件、上传、下载或读取文字。主机能撤销客户端；停止服务使旧连接凭据失效。公开文件使用内部 ID，不接受任意文件系统路径。

本版本使用局域网 HTTP，**不加密**。令牌和内容可能被同网段具备截获能力的设备读取；仅用于可信网络。SHA-256 用于完整性检查，不代表端到端加密。多个获准设备共享同一传输空间。

详细请求与恢复规则见 [PROTOCOL.md](PROTOCOL.md)。
