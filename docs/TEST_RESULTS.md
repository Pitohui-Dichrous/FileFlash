# 验证结果与兼容性

当前验证日期：2026-10-21。兼容测试版：`0.1.1-harmony4.2.1`，分支 `harmonyos-4.2`。

## 鸿蒙兼容分支当前验收

- 官方 AOSP API 29（Android 10）及 API 31（Android 12）专用模拟器各通过 40 项检查。原 Android 主线 APK 在两者均被安装器以 `INSTALL_FAILED_OLDER_SDK` 拒绝；本分支签名 APK 正常安装、无需请求旧系统不存在的通知权限即可开启前台传输服务。
- 实际完成 6 MiB 以上多分块传输、进程强制结束后重新配对和同一任务续传、全文件 SHA-256、系统下载文件逐字节核对、Range、完成回执重试和保存后释放内部副本。
- API 29 的旧版待保存项查询和 API 31 的新版查询均实际删除了本应用的未登记半成品，保存进度恢复、完整文件保护、过期与孤立断点删除正常。手动“丢弃”和“清理”实际点击通过，清理期间的活动上传继续完成，已保存文件保留。
- 模拟 360 dp 窄屏、1080 dp 大屏和旋转，检查主要操作、导航、实际截图尺寸及后台传输连续性。旧模拟器将原请求的 2208 px 限制为 2160 px，测试据此调整并重新检查布局，过程记录在报告中。这些是窗口尺寸模拟，不是 Mate X5 的实体折叠姿态测试。
- 桌面 WebKit 直接连接 API 31 模拟器内的签名 APK，完成 4 MiB + 173 字节上传、2 MiB 后网络中断、重载与选择原文件恢复、下载内容校验、文字、空文件和多文件队列；见 `test-evidence/harmony-webkit-apk.txt`。
- 20 项核心测试通过，Android lint 为 0 错误；全部 Core 生产源码另使用官方 API 29 的 `android.jar` 独立编译成功，226 个运行时成员均已解析，最高要求 API 26。见 `test-evidence/harmony-core-api29.json`。
- 源码 ZIP 在全新目录使用已有公开依赖缓存离线重新构建成功，并通过 20 项核心测试；未使用工作区签名私钥，日志见 `test-evidence/harmony-clean-build.txt`。
- 兼容 APK 最低 API 29、目标 API 37、版本代码 3，包含 ARM64 等架构，v1 / v2 签名分别验证通过，证书与 Android 主线一致。生产修改只存在于兼容分支，Android `main` 保持原版本。

最终模拟器记录见 `test-evidence/harmony-api29.json`、`test-evidence/harmony-api31.json`，记录了被测 APK 的 SHA-256。**尚未在华为 Mate X5 / HarmonyOS 4.2.0 或实体 iPhone 上验证**；模拟器安装通过不能保证华为安装器、真实 Wi-Fi、锁屏和厂商省电策略的行为。具体操作与官方依据见 [HARMONYOS_4_2.md](HARMONYOS_4_2.md)。

- 20 项核心测试通过，覆盖取消后删除断点、过期及容量维护、活动请求保护、私有副本释放、重启后的完成确认、隐藏共享后不重新公开、异常中间状态恢复和安全目录边界。
- Android lint 无错误；签名 Release APK 保持同一项目证书，可覆盖升级 0.1.0。
- Android 14 专用模拟器的 30 项缓存相关检查通过：升级保留文件、成功保存后自动释放副本、重启后同一文件和完成确认可用、孤立与过期断点清理、完整待保存文件保护、单项丢弃、批量清理期间活动上传继续完成、崩溃保存恢复、卸载及干净重装。卸载后 10 个既有及已保存文件的 SHA-256 保持一致。最终结果见 `test-evidence/cache-android.json`。

- 当前网页在桌面 Chrome 和桌面 WebKit 分别通过夹具与真实内核测试；新增检查完成历史容量和期限、暂停记录保留、已完成文件及密钥引用释放、失效断点从零重发、取消失败时保留恢复能力。见 `test-evidence/cache-browser.txt`。

存储策略、手动入口与卸载限制见 [STORAGE_PRIVACY.md](STORAGE_PRIVACY.md)。本页的 Android 存储专项结果以 `test-evidence/cache-android.json` 为准。

## 实际大文件

通过真实 HTTP 上传并完整下载 **4,295,032,835 字节**（4 GiB + 65,539 字节）。服务的 Java 堆上限为 **128 MiB**，客户端仅使用有限缓冲；完整文件不进入内存。

测试包含强制结束服务进程、追加未提交尾部、重新配对、恢复凭据检查、截断未提交尾部、继续上传，以及超过 4 GiB 位置的 Range 内容核对。最终上传和下载长度、SHA-256 均一致。

最终一次运行摘要：

```text
SHA-256: bb4cc536bdc3d8f96e2b500babbc6bd28323ed695f86ce6b23a4eb4e782e1067
Range 起点: 4295032771
实际运行: 126 秒
环境: Windows JVM / 实际 HTTP
连接失败重试: 0 次
```

该结果证明当前内核可以处理超过 4 GiB 的数据与偏移，不代表任何手机、存储设备或 Wi-Fi 都能达到相同速度。

网页内置的增量 SHA-256 另外处理了相同长度的数据，与 Node.js 标准加密库结果一致，覆盖 32 位字节/位计数边界，输入缓冲保持 2 MiB。

## 使用边界

HTTP 未加密，仅在可信网络使用。Safari 上传应保持页面在前台。浏览器重载续传需要原文件和网站保存的恢复记录；IP 或端口改变会改变网页来源，可能需要从头发送。主机优先复用端口，冲突时会选择可用端口并更新二维码。

Android 保存接收文件期间需要约两倍文件大小的空间，可靠保存后自动释放私有重复副本。保存失败会保留已验证的完整文件并提示重试；批量清理保留等待保存的唯一完整副本，不删除原文件和系统下载目录中的已保存文件。

原生客户端的“暂停”保留断点和临时数据以便重试；“记录 → 清理”经确认后删除闲置断点，单个任务可“丢弃”。自动维护使用 24 小时失活期限、256 MiB 共享闲置目标和 30 分钟近期保护，不构成所有存储的硬上限。应用进程已终止时在下次启动补做清理。

卸载会删除应用私有缓存和设置，已保存的公共下载文件保留。保存过程中被强制终止并立即卸载时，隐藏的未完成 MediaStore 项可能等待系统过期回收；不能承诺所有场景下外部目录立即零残留。
