# 验证结果与兼容性

验证日期：2026-10-21。交付版本：0.1.5-test.1 预发布版。下文保留旧版基线，并单独标明本次重跑范围。

## 0.1.5-test.1 网页连续上传

根据用户允许失败后重传的使用方式，网页改为一个 File POST 连续发送，不再预先校验原文件、逐块确认或保存断点。失败和取消会删除本轮临时数据，重试创建新任务从零开始；异常终止后在服务恢复时删除未完成连续上传。原生 Android 客户端保留原有分块、完整校验及续传协议。

- **49 项核心测试通过，Release 构建及 Android lint 无错误**。覆盖长度不符、缺失长度、部分正文 EOF、取消、停止、崩溃恢复、并行创建与状态查询，以及不误删活动下载或明确保存的文件。最低 Android 10 / API 29、同一项目签名、版本代码 7。
- 最终同一 APK 在 API 29、API 34 专用模拟器覆盖升级，各 8 项检查通过；原有公共下载文件、保存账本及 MediaStore 行保持一致。另验证认证诊断、合成探测、单次 10 MiB 连续上传与丢弃，以及原生 2 MiB 分块和幂等重发。见 `test-evidence/transport-upgrade-emulator-5554.json`、`transport-upgrade-emulator-5556.json`。
- 桌面 Chrome 和 WebKit 的连续上传夹具各通过 12 组检查：实际请求体为 File，发送不调用 Blob.arrayBuffer 或发送端 SHA；覆盖最终确认、丢失确认后清理、新任务重传、取消、空文件、队列、文字与诊断。见 `test-evidence/stream-browser-chromium.json`、`stream-browser-webkit.json`。
- 两种桌面引擎的真实 Java 服务上传、失败重传、临时中转下载与诊断通过，WebKit 的 iPhone / iPad 特征识别也通过。桌面 WebKit 另向最终签名 APK 单次上传 21,750,204 字节文件，六个空闲连接并存、JavaScript 文件读取次数为 0，独立 C 页面可在 A 未保存时下载且内容一致。见 `test-evidence/stream-desktop-live.txt`、`stream-relay-webkit-android.json`；这仍不是实体 iOS。
- **实际 Android 14 WebView 单轮控制测试**：同一模拟器内，60 MiB 合成文件由 0.1.4 的 30 个分块请求、含最终确认 3,599.8 ms，变为本版 1 个 File POST、1,024.7 ms。当前上传主线程 SHA 调用为 0；服务器边收边算接收摘要约 37.9 ms，末尾数据同步约 163.7 ms。Android Java HttpURLConnection 原分块路径仍通过，30 块加最终确认约 1,279.3 ms。见 `test-evidence/transport-webview-api34*.json`、`transport-native-api34*.json`。这是本机模拟器回环及合成可定位文件提供器，不能推出实体 Wi-Fi 的耗时，也没有复现用户的 30 秒。
- 新网页协议通过真实 HTTP 单请求发送 **4,295,032,835 字节**，Java 堆上限 128 MiB，源缓冲 128 KiB。服务器摘要、独立 C 会话完整下载摘要和源摘要一致，超过 4 GiB 的 Range 正确；断线、取消和真正强制结束后的残留清理通过。见 `test-evidence/browser-stream-large.json`。该项是 JVM 协议验证，没有冒充真实浏览器或手机测试。
- 原生协议的 4 GiB 上传、强制重启续传、前缀摘要、Range 与完整下载也重新通过，76 秒，使用 1 次有界分块重试。见 `test-evidence/large.json`。
- 源码 ZIP 在全新目录、不含签名文件及本地工程配置的情况下，使用公开依赖缓存离线构建 Debug APK 并通过全部 49 项核心测试。见 `test-evidence/browser-clean-build.txt`。

用户确认 iPhone 17 Pro / iOS 27 在 ROG 9 Pro、红魔 9 Pro 服务端均可复现旧版问题。**本版尚未经该实体 iPhone 验证，不能宣称已修复 iOS**。网页现在可复制前后端阶段诊断，合成探测不落盘；具体操作见 [BROWSER_DIAGNOSTICS.md](BROWSER_DIAGNOSTICS.md)。诊断报告无文件名、配对或会话凭据、IP、完整 User-Agent 及正文。

## 0.1.3 临时中转与手动保存

服务端接收完成后默认只在私有目录临时共享，不自动发布到系统下载目录。B 和 C 分别连接 A，B 上传后 C 可直接下载，A 无须点保存；A 明确点保存时才导出到“下载 / FileFlash”。原生客户端主动点击接收的保存流程保持不变。

- **34 项核心测试通过**。新增跨会话中转与重启、临时完整文件与断点共用 TTL/预算、实际下载起止续期、轮询/HEAD/下载链接不续期、打开源文件前的下载保护、保存意图持久保护、升级前数据保护，以及丢弃后的共享/凭据/回执同步失效。
- Android lint 无错误，签名 Release 继续最低 API 29、目标 API 37，保持同一项目证书。
- 最终同一签名 APK 在 **Android 10 / API 29、Android 14 / API 34 专用模拟器各 18 项、合计 36 项通过**：覆盖升级保留文件、B/C 独立会话、上传后不创建 MediaStore 副本、C 下载、停止共享后手动保存及副本释放、丢弃、手动清理、混合重启恢复，以及通过仅修改本轮文件时间验证启动时自动过期。还注入“已保存系统文件删除、私有副本因中断保留”的现场，确认私有源仍可管理和丢弃；该项是故障注入，未伪称真实下载竞争。见 `test-evidence/relay-android-api29.json`、`relay-android-api34.json`。
- 网页 Chrome / WebKit 协议夹具及实际 Java 服务回归通过，仍覆盖 512 KiB iPhone 兼容路径、确认丢失恢复、错误文件拒绝和重载续传。见 `test-evidence/relay-browser.txt`。
- 桌面 WebKit 模拟 iPhone 的 B 页面向最终 APK 上传 **21,750,204 字节 APK**，在六个空闲连接和故意丢失一次 2 MiB 后分块确认的情况下自动恢复；C 使用独立浏览器上下文配对，在 A 未保存时直接下载，字节和 SHA-256 一致。首次只读 512 KiB 即发送，保留上传性能修复；见 `test-evidence/relay-webkit-android.json`。这是模拟浏览器特征及 ADB 转发测试，不能代替实体 iPhone 和 Wi-Fi。
- 4 GiB + 65,539 字节的真实 HTTP 上传、前缀摘要、强制重启续传、Range 与完整下载重新通过，Java 堆上限 128 MiB。见 `test-evidence/large.json`。
- 当前程序源码在全新目录、没有签名私钥及本地工程配置时，使用公开依赖缓存离线构建 Debug APK 并通过 34 项核心测试。见 `test-evidence/relay-clean-build.txt`。

未保存的临时中转文件现纳入 24 小时无活动过期及 256 MiB 闲置目标；预算回收保护最近 30 分钟使用的数据。活动上传/下载/保存、保存失败待重试及升级前完整待保存数据受保护。临时中转仍占用 A 的私有空间，256 MiB 不是所有存储的硬上限；进程不运行时在下次启动清理。

## 0.1.2 上传修复与最低系统

用户在实体 iPhone 的 Chrome 和 Safari 上均报告上传停在 2 MiB，而 Android 客户端正常。旧版网页把浏览器发出字节当成接收进度，2 MiB/4 MiB 因此不能证明接收端已经保存了这些字节。另在旧内核独立复现六个空闲 TCP 连接占满工作线程、下一块与状态查询一起等待的问题；这是一项确定缺陷，但尚不能认定为该 iPhone 现象的唯一原因。

- 首次上传改为边读边传并增量计算 SHA-256；仍验证分块和最终完整文件。重选文件续传只核对已经提交的前缀，兼容旧版已声明完整摘要的任务。
- 主进度只统计接收端确认的字节。丢失回复时查询断点并重发同块，服务端做幂等验证；最多自动重试 3 次。暂停和取消可以打断恢复，校验或权限错误不会盲目重发。
- iPhone/iPad 网页单次请求降为 512 KiB，降低单次请求及重试成本；不把它解释成 iOS 的固定大小限制。其他客户端仍最多 2 MiB。
- 请求头改用独立非阻塞就绪阶段，空闲及不完整请求头不占传输线程；上限 48 个待请求头连接、16 KiB/连接和 5 秒绝对期限。修复提前拒绝正文时 TCP 重置掩盖错误回执的问题。
- 最低 Android 调整为 **Android 10 / API 29**，目标 API 37。依据是现有 MediaStore Downloads 保存流程最低需要 API 29；补齐通知权限、待保存项查询和旧系统备份规则。全部核心 Java 源文件通过 API 29 SDK 符号编译检查。
- **26 项核心测试通过**，新增空闲/半请求头连接、并发分块可用性、请求头上界和期限、二进制预读完整性、前缀摘要及其鉴权、重启与清理边界。Android lint 无错误，最终 Release 签名与旧版一致。
- 桌面 Chrome、WebKit 的协议夹具与真实 Java 服务均通过：丢确认、提交前断线、确认前不虚增进度、错误文件和最终损坏拒绝、恢复期间暂停/取消、页面重载及同任务恢复。iPhone UA、iPad 桌面模式特征下通过 512 KiB 首块、最终内容与旧版 2 MiB 断点续传。见 `test-evidence/ios-upload-browser-*.json`、`ios-upload-live-*.json` 及日志。
- 最终同一签名 APK 在 **API 29、API 34 专用模拟器各 14 项检查通过**：覆盖升级保留旧文件、多块接收、前缀摘要、系统下载目录保存、重复副本释放、重启回执和下载内容一致。API 29 从此前兼容实验版覆盖升级，保留 3 个已有文件；这不是华为真机验证。见 `test-evidence/upload-android.json`、`upload-android-api29.json`。
- 桌面 WebKit 模拟 iPhone 特征，直接向最终 APK 上传 **21,750,204 字节 APK**：首次只读 524,288 字节便发出请求；六个空闲 TCP 连接并存时，故意丢弃 2 MiB 后一块的成功确认，自动恢复完成，无须手动重试；最终 SHA-256 和浏览器下载内容均一致。见 `test-evidence/upload-webkit-android.json`。
- 源码 ZIP 在全新目录、不含本地签名文件的条件下，使用已有公开依赖缓存离线重新构建 Debug APK，并通过全部 26 项核心测试。见 `test-evidence/upload-clean-build.txt`。

实体 iPhone 上的本次修复仍待复测；桌面 WebKit 和模拟 iPhone 特征不能替代 iOS 系统网络、文件选择器及真实 Wi-Fi。Android 9 及以下没有旧版存储实现，当前不支持。

## 实际大文件

通过真实 HTTP 上传并完整下载 **4,295,032,835 字节**（4 GiB + 65,539 字节）。服务的 Java 堆上限为 **128 MiB**，客户端仅使用有限缓冲；完整文件不进入内存。

测试包含强制结束服务进程、追加未提交尾部、重新配对、恢复凭据检查、截断未提交尾部、继续上传、超过 4 GiB 的已提交前缀摘要，以及超过 4 GiB 位置的 Range 内容核对。最终上传和下载长度、SHA-256 均一致。

最终一次运行摘要：

```text
SHA-256: e3111d957c1dc03414015b5a64fad5b9277998e503a014604f489efb885ca6cd
Range 起点: 4295032771
实际运行: 76 秒
环境: Windows JVM / 实际 HTTP
连接失败重试: 1 次
```

该结果证明当前内核可以处理超过 4 GiB 的数据与偏移，不代表任何手机、存储设备或 Wi-Fi 都能达到相同速度。

网页内置的增量 SHA-256 另外处理了相同长度的数据，与 Node.js 标准加密库结果一致，覆盖 32 位字节/位计数边界，输入缓冲保持 2 MiB。

## 使用边界

HTTP 未加密，仅在可信网络使用。Safari 上传应保持页面在前台。浏览器重载续传需要原文件和网站保存的恢复记录；IP 或端口改变会改变网页来源，可能需要从头发送。主机优先复用端口，冲突时会选择可用端口并更新二维码。

Android 保存接收文件期间需要约两倍文件大小的空间，可靠保存后自动释放私有重复副本。保存失败会保留已验证的完整文件并提示重试；批量清理保留等待保存的唯一完整副本，不删除原文件和系统下载目录中的已保存文件。

原生客户端的“暂停”保留断点和临时数据以便重试；“记录 → 清理”经确认后删除闲置断点，单个任务可“丢弃”。自动维护使用 24 小时失活期限、256 MiB 共享闲置目标和 30 分钟近期保护，不构成所有存储的硬上限。应用进程已终止时在下次启动补做清理。

卸载会删除应用私有缓存和设置，已保存的公共下载文件保留。保存过程中被强制终止并立即卸载时，隐藏的未完成 MediaStore 项可能等待系统过期回收；不能承诺所有场景下外部目录立即零残留。

测试入口和复现方法见 [TESTING.md](TESTING.md)。机器可读结果位于本目录的 `test-evidence`。
