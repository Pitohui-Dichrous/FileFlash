# 浏览器上传诊断

0.1.8 保留浏览器诊断；照片与视频使用[系统分享入口](IOS_SHARE.md)。诊断也可读取快捷指令请求的服务端阶段。

## 快捷指令卡住时

运行后前 60 秒内回到已连接的 Safari 网页，点「连接状态 → 诊断 → 复制诊断」。不要先停止安卓共享。报告不含媒体内容、文件名或凭据。

`shortcut-upload` 无请求而 `pair` 已成功，说明还停在客户端准备或动作执行；请求已到但 `receivedBytes=0`，说明正文尚未送达；字节增加说明正在传输。`status=200` 且 `flushed=true` 表示服务端已完成并写出回执，但不能证明手机收到。结合报错高亮动作可区别上传与回执处理。最近 128 次连接可能被后续轮询覆盖，不必等多轮超时后再复制。

## 诊断

1. Android 覆盖安装 0.1.8，重新开启共享；iPhone 用 Safari 重新扫码、刷新页面，保持页面在前台。
2. 点网页右上角连接状态，展开连接详情，点“诊断”。不必选择个人文件。
3. 结束后点“复制诊断”，把整段文字发回当前对话。若提示已选中文字，请长按文本框并选择“复制”。

如果实际文件已经上传失败，直接在该任务上点“诊断”及“复制诊断”即可，报告会带上这次失败的发送阶段。复制之前不要刷新页面或停止共享，以免丢失本轮内存记录。

诊断使用四份各 512 KiB 的合成数据，对比 XHR POST、fetch PUT / POST，以及内存 ArrayBuffer / Blob；探测阶段总预算 12 秒，随后读取服务端记录。合成数据只在内存中处理，不创建传输任务，不进入接收目录或系统下载目录。

诊断不会自动重传原文件。如果探测确认 fetch POST 可用，本页面会记住选择；需要继续时手动点失败任务的“重试”。诊断成功仅说明合成请求可通过，不保证原文件上传已解决。

本版网页将原 File 用一个 POST 连续发送，不预读整文件、不计算发送端 SHA、不逐块等待确认。接收端核对总长度，边接收边计算摘要，仅在末尾同步和确认；摘要用于回执，不与发送端摘要比对。网页不再提供暂停或断点恢复；中断时删除该任务的临时数据，重试从零创建任务。原生应用之间的分块、校验和续传流程保留。

接收完成仍是私有临时中转，只有服务端用户点“保存”才进入系统下载目录。丢失确认后的未保存完整临时文件也可清除；已经保存或正在使用的文件受保护。

## 报告内容与边界

报告包含粗略平台类别、发送字节数、请求方式、HTTP 状态和阶段耗时。网页另保留最近 32 条选取事件，即使还没有形成上传任务也可记录打开、收到结果或未取得文件；不以失焦、回到页面或固定时限猜测选取失败。服务端最多保留最近 128 条请求记录，全部仅存内存；读取报告和运行探测均要求已配对的有效会话，并检查请求来源。报告不包含设备名称、文件名、配对令牌、会话或恢复密钥、IP 地址、原始 User-Agent、文件内容或请求正文。每次请求的随机标识仅用于对应前后端记录。

服务端阶段可区分请求头未完成、正文收到零字节或部分字节、等待任务锁、校验、写入、磁盘同步及回复写出。`flushed` 表示回复已写入本机网络连接，不能证明 iPhone 已收到。支持合法 `Expect: 100-continue` 握手；仅系统分享专用的 `POST /api/shortcuts/files` 接受受限的 chunked 编码，其他路由仍拒绝 `Transfer-Encoding`。

本次 70 项核心测试通过，覆盖诊断认证、隐私与容量边界、部分正文与 EOF、协议提前拒绝、100 Continue、内存探测，以及连续上传的长度、清理、并行创建、重启和保存保护。最终设备及性能证据见 [TEST_RESULTS.md](TEST_RESULTS.md)。
